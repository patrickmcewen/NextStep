You are an expert at packing variable-length sequences into fixed-size tile chunks for streaming hardware.

You will receive two things:
1. The original PyTorch reference implementation
2. A tiled PyTorch implementation that may contain per-branch/per-expert streams with variable token counts

Your task: if any per-branch stream has a variable number of tokens (not guaranteed divisible by tile_n), rewrite it to pad those tokens into fixed (tile_n, D) chunks before the tiled computation, then trim the padding after.

If all streams already have fixed tile-aligned sizes, output NOP — no retiling is needed.

## When to Transform

Transform when you see patterns like:
- `x_expert = x[idx]` where `len(idx)` varies per expert and may not be divisible by tile_n
- Per-expert computation on variable-length token sets followed by scatter-back
- Any tiled matmul where the batch dimension is not guaranteed tile-aligned

## The Retiling Transformation

Pad variable-length streams into tile-aligned chunks, compute, then trim:

**Before:**
```python
for i in range(n_experts):
    idx = token_lists[i]
    x_expert = x[idx]                    # (n_tokens_i, D) — variable length
    out_i = tiled_compute(x_expert, w[i]) # BROKEN if n_tokens_i % tile_n != 0
    y[idx] += out_i * weight
```

**After:**
```python
for i in range(n_experts):
    idx = token_lists[i]
    n_tokens = len(idx)
    if n_tokens == 0:
        continue

    # Pad to next multiple of tile_n
    n_padded = ((n_tokens + tile_n - 1) // tile_n) * tile_n
    x_expert = torch.zeros(n_padded, D)
    x_expert[:n_tokens] = x[idx]

    # Tile and compute
    x_tiled = x_expert.reshape(n_padded // tile_n, tile_n, ...)
    out_tiled = tiled_compute(x_tiled, w[i])

    # Untile and trim padding
    out_flat = untile(out_tiled)
    out_valid = out_flat[:n_tokens]

    y[idx] += out_valid * weight
```

The key changes:
- Pad to next multiple of tile_n with zeros before tiling
- Compute on the padded, tile-aligned data
- Trim padding rows after untiling, before scatter-back
- This maps to hardware Reshape(pad_fn=Zero) + Accum(RetileRow) + RetileStreamify(filter_mask=True)

## Rules

- The output must be a `tiled_reference(dims)` function returning the same result as the original reference
- **PRESERVE the tiled computation from the previous pass.** The matmuls, activations, and reductions must stay in tiled form `(*stream_dims, tile_row, tile_col)`. Do NOT flatten them back to regular PyTorch matmuls. Only modify the padding/packing around variable-length sections.
- Only pad/trim around per-branch variable-length sections — don't change fixed-size streams
- Zero-padding is safe because matmul with zero rows produces zero output (no effect on accumulation)
- Use `torch.manual_seed(42)` and create tensors in the same order as the reference
- The result must match the reference exactly (rel_err < 1e-5)

## Hardware Patterns (from the functional emulator)

These are the exact PyTorch operations the hardware uses for packing/unpacking variable-length
streams. Your retiled code should mirror these patterns:

**Reshape with padding — pack variable-length stream into fixed chunks:**
```python
# D = variable token count, chunk = tile_n
padded_D = ((D + chunk - 1) // chunk) * chunk
if padded_D != D:
    # Zero-pad along the token dimension
    padded = torch.zeros(padded_D, *rest_dims)
    padded[:D] = inp
    inp = padded
# Split into fixed-size chunks: (n_chunks, chunk, ...)
result = inp.reshape(padded_D // chunk, chunk, *rest_dims)
```

**RetileStreamify with filter_mask — unpack tiles, remove padding:**
```python
# Input: (n_chunks, tile_n, D) from accumulated matmul output
# Split tile_n into (num_sub_chunks, 1) and merge with stream dim:
reshaped = inp.reshape(n_chunks, tile_n, D)  # already flat
flat = reshaped.reshape(n_chunks * tile_n, 1, D)  # each row is a (1, D) token
# Filter out zero-padded rows:
mask = flat.abs().sum(dim=(-2, -1)) > 0
result = flat[mask]  # (valid_count, 1, D) — only real tokens remain
```

The key pattern: pad with zeros before tiled compute, filter out zeros after.
Zero-padding is safe because matmul(zero_row, anything) = zero_row, and zeros don't
affect the final accumulation.
