## What You Are Doing

The tiled PyTorch code creates tensors with `torch.randn(...)` and then reshapes/permutes them into tiled layout `(*stream_dims, tile_r, tile_c)`. You will replace each such pattern with a `LinearOffChipLoad` node that produces the same tiled tensor via the hardware's strided tile loader.

## The Translation

**Before (tiled PyTorch):**
```python
# Create weight and tile it
w = torch.randn(D, F_dim)
w_tiled = w.reshape(D, grid_f, tile_f).permute(1, 0, 2)  # (grid_f, D, tile_f)
# Later: broadcast across batch

```

**After (hybrid with STeP load):**
```python

# Load via STeP LinearOffChipLoad — produces (1, *out_shape_tiled, tile_r, tile_c)
graph = Graph()
w_load = LinearOffChipLoad(
    underlying=w,
    stride=(F_tiles, 1),       # row-major tile grid: D-tiles stride by F_tiles, F-tiles stride by 1
    out_shape_tiled=(D_tiles, F_tiles),
    tile_row=D, tile_col=tile_f,
    par_dispatch=4,
)
graph.add_node(w_load)
graph = infer_broadcast(graph)
values = execute_values(graph)
w_tiled = values[w_load.instance_id]  # (1, D_tiles, F_tiles, D, tile_f)

# CRITICAL: The emulator always prepends a leading dim of size 1.
# You MUST squeeze(0) to get the shape the tiled code expects:
w_tiled = w_tiled.squeeze(0)  # (D_tiles, F_tiles, D, tile_f) — matches tiled code layout
```

## CRITICAL: Output Shape from execute_values

`execute_values` returns tensors with shape `(1, *out_shape_tiled, tile_r, tile_c)`.
The leading `1` is NOT part of your stream/tile layout. You MUST call `.squeeze(0)` on
every tensor you extract from `values[...]` before using it in downstream PyTorch ops.
Failure to do this causes dimension mismatches in every subsequent reshape/permute/matmul.

## How LinearOffChipLoad Works

The underlying 2D tensor `(R, C)` is divided into a grid of `(R//tile_r, C//tile_c)` tiles, stored in row-major order as a flat array of `grid_r * grid_c` tiles.

`stride` and `out_shape_tiled` define how to index into this flat array:
```python
linear_idx = sum(grid_coord[d] * stride[d] for d in range(len(stride)))
tile = flat_tiles[linear_idx]
```

Key stride patterns:
- **Simple 2D load** `(R, C)` with tiles `(tr, tc)`: `stride=(C//tc, 1)`, `out_shape_tiled=(R//tr, C//tc)`
- **Broadcast a dimension**: use `stride=0` for that dimension. The grid coordinate doesn't change the tile index, so the same tiles repeat.
- **GEMM pattern** — both A and B on the same grid `(M//tm, N//tn, K//tk)`:
  - A `(M, K)`: `stride=(K//tk, 0, 1)` — 0 on N means A repeats across N
  - B `(K, N)`: `stride=(0, N//tn, 1)` — wait, that's wrong. B is `(K, N)` with tiles `(tk, tn)`, grid is `(K//tk, N//tn)`. For out_shape `(M//tm, N//tn, K//tk)`: `stride=(0, 1, N//tn)` — 0 on M means B repeats across M, N-tiles stride by 1, K-tiles stride by `N//tn`.

The output shape is always `(1,) + out_shape_tiled + (tile_r, tile_c)` — note the leading 1 dimension prepended by the emulator.
