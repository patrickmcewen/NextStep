{call_site_rules_section}## Stream-Shape Invariant

Every ``out_shapes`` entry — and every tile-stream tensor in your function — is a **STeP stream**, which always has rank >= 3: at least 1 stream dim followed by exactly 2 tile dims (``tile_row``, ``tile_col``). Concretely:

- **Allowed:** ``out_shapes=((S, T_R, T_C),)`` (one stream dim), ``out_shapes=((B, S, T_R, T_C),)`` (two stream dims), and so on. The trailing two dims are always the tile.
- **Forbidden:** vanilla 2D shapes like ``out_shapes=((M, N),)`` or any 1D / 0D shape. Such a request cannot be a tile stream and the orchestrator will reject the contract loudly at the parent's call site.
- The child blackbox stub only reshapes its underlying reference output to the requested ``out_shapes`` entry. If you need a stream layout that pure reshape can't reach (e.g. moving the seq axis to the front), apply the permutation on the stub's return via DSL ops (``bufferize`` + ``streamify`` with proper strides).

If the parent reference's vanilla output is 2D, you still produce a stream by promoting it to >= 3D using a DSL op (e.g., ``streamify`` to attach a stream dim, or factor the vanilla axes into a stream-plus-tile decomposition consistent with how the rest of the kernel tiles its data).

## NOTE ABOUT LOADS

Every tensor that reaches a DSL **consumer** (any binary_*, unary_*, accum_*, reshape_*, promote_*, broadcast/parallelize/static_reassemble, eager_merge, flat_partition/flat_reassemble, flatmap_*, streamify/bufferize/retile_streamify, repeat_*, expand_ref, offchip_store, …) must come from an on-chip source — a DSL **producer** (`offchip_load`, `offchip_load_ref`, `dyn_offchip_load`, `random_offchip_load`, `select_gen`, `metadata_gen`, `expert_addr_gen`, `cache_read_addr_gen`, `filter_last_tile`){load_source_tail}, or another consumer's output. **Off-chip values must be loaded first.** Off-chip means:
- **At the root:** any `tensors["X"]` read.
- **At a non-root node:** any positional argument the contract block above tags **RAW**. The parent's call site forwarded that tensor without loading it; you have to load it here before any DSL consumer touches it.

{offchip_subject_lead} **must not** flow into a DSL consumer until they have passed through `offchip_load` (or another producer). This rule is enforced by an AST dataflow check; a violation looks like:
```
- `binary_matmul` consumes `o_proj_weight` which is a raw positional arg ...; load it via `offchip_load` ... before passing to a DSL consumer.
```
Fix it by loading the value into a stream first, e.g. ``W = offchip_load(o_proj_weight, ...)``, and feeding ``W`` into the consumer.

Args tagged **on-chip** in the contract block are already streams (the parent emitted them from a sibling DSL op{onchip_source_tail}); pass them directly to consumers without an extra load.

Some positional args may arrive as Python lists rather than tensors. The contract block tags these with ``list[Tensor(...)] x N`` (e.g. per-expert weight stacks): iterate at host time and emit one DSL op per element. The natural pattern is ``loads = [offchip_load(w_list[i], ...) for i in range(len(w_list))]`` — the list is preserved at the lowering target as N parallel structural graph nodes (one off-chip load per expert), so the static for-loop here is the right shape, not a placeholder. Do **not** pass the list itself to a DSL consumer.

## Stride Convention

`stride` and `out_shape_tiled` define how tile indices map to positions in the underlying tensor's tile grid.

- **Advancing dim**: `stride[i] = grid_cols_per_step` — tiles advance through the grid
- **Broadcast dim**: `stride[i] = 0` — same tile replicated along this dimension

## Off-Chip Sink (root only)

The root function (`tiled_reference`) is the only place where the kernel writes its result off-chip. It **must** terminate with a single `offchip_store(...)` whose argument is the stream that carries the kernel's output. This holds regardless of how the root's body is structured{root_orchestrator_alt_clause} — the final value must be wrapped in `offchip_store(...)`:

```python
def tiled_reference(dims, tensors):
    ...
    return offchip_store(<final_stream>)
```

Non-root functions **must not** call `offchip_store`. They hand a stream tensor up to their parent (via `return`); the parent (and ultimately the root) is responsible for the off-chip write. The regex compliance check rejects a root that omits `offchip_store`.

The judge will reject any function whose name or signature deviates from the one rendered in the user prompt.

## Reference: dynamic-sequence-length KV-cache idiom

When a kernel reads per-request K/V tiles whose count varies per batch row, then splices a new token's row into the last existing tile, the canonical STeP composition is:

  ragged read → filter last tile → splice → reassemble → matmul + accum

The accum at the end **absorbs the ragged sequence dim**, so the visible output is per-request — no `max_seq` padding leaks past `offchip_store`. Equivalently: never call `offchip_store` on a stream whose innermost stream dim is the ragged one; reduce it away first (typically with `binary_matmul + accum_add(rank=<ragged_dim>)`).

Key conventions in this idiom:

- `idx`, `seq_len`, `offset` arrive as `[B]`-shaped `(tile 1,1)` metadata via `metadata_gen` (or are pre-emitted as such by the parent). `seq_len` is the tile count **after** the append. The IR rewriter auto-broadcasts a metadata source to multiple consumers — write each consumer call as if you were passing the original tensor, do not hand-roll `broadcast`.
- `cache_read_addr_gen(idx, seq_len, row_offset)` reads `seq_len` tiles per row and attaches per-row lengths to the output stream; `random_offchip_load` then zeros padded slots automatically. Padded zero K means padded slots contribute zero through any downstream matmul, so `accum_add` over the ragged dim is identical to summing only the real tiles.
- `filter_last_tile(seq_len)` picks the tile at index `seq_len-1` of each row; pair it with `flat_partition(..., n=2, partition_rank=0)` to split out the last tile from the prefix. Padded rows have all-zero multihot, so they drop out of both branches naturally.
- `binary_set_offset` followed by `binary_row_wise_append` splices the new token row into the last tile at row `offset`. Flatten the metadata stream into the data stream's shape first (`flatten(..., min_rank=0, max_rank=1)`) so the binary maps line up. The V variant has the same shape: rename `_k` → `_v` and reuse the same `seq_len` / `offset` (one shared `idx` per request).
- `flat_reassemble([last_updated, prefix], control=last_sel, reassemble_rank=0)` rejoins the spliced last tile with the prefix; the trailing singleton stream dim it produces is folded back via `flatten(..., min_rank=0, max_rank=1)`.

```python
def tiled_reference(dims, tensors):
    B          = dims["B"]
    D          = dims["D"]
    tile_N     = dims["tile_N"]
    ROW_OFFSET = dims["maxN"] // tile_N

    # Metadata: idx (cache slot), seq_len (tile count after append),
    # offset (intra-tile row for the new token).
    idx     = metadata_gen(tensors["idx"])
    seq_len = metadata_gen(tensors["seq_len"])
    offset  = metadata_gen(tensors["offset"])

    # Ragged-K cache read: padded tile slots are zeroed by random_offchip_load
    # because cache_read_addr_gen tagged the output with per-row lengths.
    raddr   = cache_read_addr_gen(idx, seq_len, row_offset=ROW_OFFSET)
    k_tiles = random_offchip_load(
        tensors["cache"], raddr=raddr, tile_row=tile_N, tile_col=D,
    )

    # New token row (one row per request) to splice into the last tile.
    new_k = offchip_load(
        tensors["new_k"], stride=(1,), out_shape_tiled=(B,),
        tile_row=1, tile_col=D,
    )

    # Split out the last tile, splice new_k into row `offset`, then rejoin.
    last_sel = filter_last_tile(seq_len)
    last_tile, prefix_tiles = flat_partition(
        k_tiles, last_sel, n=2, partition_rank=0,
    )
    offset_flat   = flatten(offset, min_rank=0, max_rank=1)
    new_k_flat    = flatten(new_k,  min_rank=0, max_rank=1)
    last_with_off = binary_set_offset(last_tile, offset_flat)
    last_updated  = binary_row_wise_append(last_with_off, new_k_flat)
    appended_k    = flatten(
        flat_reassemble(
            [last_updated, prefix_tiles],
            control=last_sel, reassemble_rank=0,
        ),
        min_rank=0, max_rank=1,
    )

    # Optional: write the updated last tile back to the cache. The cache
    # is an off-chip side effect; the kernel's *output* still flows through
    # offchip_store at the bottom of the function.
    waddr      = binary_cache_write_addr_gen(idx, seq_len, row_offset=ROW_OFFSET)
    waddr_flat = flatten(waddr, min_rank=0, max_rank=1)
    random_offchip_store(
        tensors["cache"], wdata=last_updated, waddr=waddr_flat,
        tile_row=tile_N, tile_col=D,
    )

    # Per-request Q . K^T over the ragged seq dim, then absorb the ragged
    # dim with accum_add(rank=1). Output stream rank is 2; no max_seq leak.
    q = offchip_load(
        tensors["Q"], stride=(1,), out_shape_tiled=(B,),
        tile_row=1, tile_col=D,
    )
    q_expanded = repeat_ref(q, appended_k)
    qkt        = binary_matmul(q_expanded, appended_k, weight_transposed=True)
    pooled     = accum_add(qkt, rank=1)
    return offchip_store(pooled)
```

This is a single-head sketch; for multi-head, lift `tensors["cache"]` / `tensors["new_k"]` / `tensors["Q"]` to carry the head dim and tile/repeat accordingly — the ragged-read / splice / reassemble / matmul-accum core is unchanged. The dims here (`B`, `D`, `tile_N`, `maxN`) are illustrative; adapt to whatever the parent contract gives you.
