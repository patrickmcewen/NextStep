## No Tensor-Method Transforms at Blackbox Call Sites

When passing a tensor to a child blackbox, **no tensor-method transform may appear between the tensor source and the call site** — the stub recovers vanilla shape internally via ``flatten().reshape(vanilla_shape)`` and applies any requested ``out_perms`` / ``out_shapes`` itself. Specifically:

- **Allowed (single-output child):** `result = child_name(x, ..., out_shapes=((S, T_R, T_C),), out_perms=(None,))`
- **Allowed (multi-output child):** `q, k, v = child_name(x, ..., out_shapes=(s_q, s_k, s_v), out_perms=(p_q, p_k, p_v))`
- **Forbidden:** `.reshape(...)`, `.permute(...)`, `.transpose(...)`, any index expression `[...]`, arithmetic (`*`, `+`, etc.), `.squeeze()`, `.unsqueeze()`, `.expand()`, `.flatten()` (any dim form)

If you need to change a stream's shape *anywhere* in the function (call sites, intermediate values, return value), use the appropriate DSL op — `reshape_stream`, `reshape_pad_stream`, `streamify`, `flatten`, `bufferize`, `retile_streamify`, etc. Never use `tensor.reshape(...)` or any other ``torch.Tensor`` method.

Both ``out_shapes`` and ``out_perms`` are **always tuples of per-output entries**. Even single-output children take a 1-tuple (e.g. ``out_shapes=((S, T_R, T_C),)``). Output permutations go in ``out_perms`` (one entry per output, ``None`` = identity); never apply ``permute``/``transpose`` to the input.

## Stream-Shape Invariant

Every ``out_shapes`` entry — and every tile-stream tensor in your function — is a **STeP stream**, which always has rank >= 3: at least 1 stream dim followed by exactly 2 tile dims (``tile_row``, ``tile_col``). Concretely:

- **Allowed:** ``out_shapes=((S, T_R, T_C),)`` (one stream dim), ``out_shapes=((B, S, T_R, T_C),)`` (two stream dims), and so on. The trailing two dims are always the tile.
- **Forbidden:** vanilla 2D shapes like ``out_shapes=((M, N),)`` or any 1D / 0D shape. Such a request cannot be a tile stream and the orchestrator will reject the contract loudly at the parent's call site.
- ``out_perms[i]`` (when not ``None``) must be a permutation over ``range(len(out_shapes[i]))`` — same rank as the matching ``out_shapes[i]``.

If the parent reference's vanilla output is 2D, you still produce a stream by promoting it to >= 3D using a DSL op (e.g., ``streamify`` to attach a stream dim, or factor the vanilla axes into a stream-plus-tile decomposition consistent with how the rest of the kernel tiles its data).

This rule, together with the no-tensor-method rule above, is enforced by the judge. Any tensor-method transform between a source and a blackbox call site, or any sub-rank-3 ``out_shapes`` entry, will result in `VERDICT: REJECT`.

## Stride Convention

`stride` and `out_shape_tiled` define how tile indices map to positions in the underlying tensor's tile grid.

- **Advancing dim**: `stride[i] = grid_cols_per_step` — tiles advance through the grid
- **Broadcast dim**: `stride[i] = 0` — same tile replicated along this dimension

## HINT: Arbitrary permutation of tensor can be expressed through a Bufferize + Streamify pair with proper strides.

For every non-root node, the user prompt's "Required Function Signature" block gives the **exact** signature you must produce — copy it verbatim. It has the form:
```python
def <node_name>(<arg_1>, <arg_2>, ..., *, out_shapes, out_perms=None):
```
where the positional parameters are the named tiled inputs declared by the parent's call-site contract (also listed in the contract block above), and the keyword-only tail is the bare `*` separator followed by `out_shapes` and `out_perms=None`. Do **not** collapse the positional list into `*intermediate_args` — that is a syntax error in combination with the keyword-only tail.

If your node's PyTorch reference returns a single tensor, your function returns a single tensor. If it returns a tuple of N tensors (e.g. ``return Q, K, V``), your function must return a tuple of the same length. ``out_shapes`` always has length N (the parent will pass a 1-tuple for single-output children). ``out_perms`` is parallel to ``out_shapes``; ``None`` entries mean the matching output keeps its native layout.

## Off-Chip Sink (root only)

The root function (`tiled_reference`) is the only place where the kernel writes its result off-chip. It **must** terminate with a single `offchip_store(...)` whose argument is the stream that carries the kernel's output. This is true regardless of whether the root's body is a leaf computation or a pure orchestrator that threads tensors through child blackboxes — even an orchestrator-style root must wrap its final value in `offchip_store(...)`:

```python
def tiled_reference(dims, tensors):
    ...
    return offchip_store(<final_stream>)
```

Non-root functions **must not** call `offchip_store`. They hand a stream tensor up to their parent (via `return`); the parent (and ultimately the root) is responsible for the off-chip write. The regex compliance check rejects a root that omits `offchip_store`.

The judge will reject any function whose name or signature deviates from the one rendered in the user prompt.
