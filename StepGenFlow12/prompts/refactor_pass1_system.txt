{call_site_rules_section}## Stream-Shape Invariant

Every ``out_shapes`` entry — and every tile-stream tensor in your function — is a **STeP stream**, which always has rank >= 3: at least 1 stream dim followed by exactly 2 tile dims (``tile_row``, ``tile_col``). Concretely:

- **Allowed:** ``out_shapes=((S, T_R, T_C),)`` (one stream dim), ``out_shapes=((B, S, T_R, T_C),)`` (two stream dims), and so on. The trailing two dims are always the tile.
- **Forbidden:** vanilla 2D shapes like ``out_shapes=((M, N),)`` or any 1D / 0D shape. Such a request cannot be a tile stream and the orchestrator will reject the contract loudly at the parent's call site.
- The child blackbox stub only reshapes its underlying reference output to the requested ``out_shapes`` entry. If you need a stream layout that pure reshape can't reach (e.g. moving the seq axis to the front), apply the permutation on the stub's return via DSL ops (``bufferize`` + ``streamify`` with proper strides).

If the parent reference's vanilla output is 2D, you still produce a stream by promoting it to >= 3D using a DSL op (e.g., ``streamify`` to attach a stream dim, or factor the vanilla axes into a stream-plus-tile decomposition consistent with how the rest of the kernel tiles its data).

## NOTE ABOUT LOADS

Every tensor that reaches a DSL **consumer** (any binary_*, unary_*, accum_*, reshape_*, promote_*, broadcast/parallelize/static_reassemble, eager_merge, flat_partition/flat_reassemble, flatmap_*, streamify/bufferize/retile_streamify, repeat_*, expand_ref, offchip_store, …) must come from an on-chip source — a DSL **producer** (`offchip_load`, `offchip_load_ref`, `dyn_offchip_load`, `random_offchip_load`, `select_gen`, `metadata_gen`, `expert_addr_gen`, `cache_read_addr_gen`, `filter_last_tile`){load_source_tail}, or another consumer's output. **Off-chip values must be loaded first.** Off-chip means:
- **At the root:** any `tensors["X"]` read.
- **At a non-root node:** any positional argument the contract block above tags **RAW**. The parent's call site forwarded that tensor without loading it; you have to load it here before any DSL consumer touches it.

{offchip_subject_lead} **must not** flow into a DSL consumer until they have passed through `offchip_load` (or another producer). This rule is enforced by an AST dataflow check; a violation looks like:
```
- `binary_matmul` consumes `o_proj_weight` which is a raw positional arg ...; load it via `offchip_load` ... before passing to a DSL consumer.
```
Fix it by loading the value into a stream first, e.g. ``W = offchip_load(o_proj_weight, ...)``, and feeding ``W`` into the consumer.

Args tagged **on-chip** in the contract block are already streams (the parent emitted them from a sibling DSL op{onchip_source_tail}); pass them directly to consumers without an extra load.

Some positional args may arrive as Python lists rather than tensors. The contract block tags these with ``list[Tensor(...)] x N`` or ``list[int] x N``:

- ``list[Tensor]`` (e.g. per-expert weight stacks): iterate at host time and emit one DSL op per element. The natural pattern is ``loads = [offchip_load(w_list[i], ...) for i in range(len(w_list))]`` — the list is preserved at the lowering target as N parallel structural graph nodes (one off-chip load per expert), so the static for-loop here is the right shape, not a placeholder. Do **not** pass the list itself to a DSL consumer.
- ``list[int]`` (e.g. per-batch sequence lengths): convert to a 1D tensor exactly once via ``torch.tensor(<list_arg>)`` and feed into ``metadata_gen`` (or ``cache_*_addr_gen`` etc.) so ragged downstream ops can read the per-row metadata. Do not iterate the list element-by-element to scalar-index DSL ops.

## Stride Convention

`stride` and `out_shape_tiled` define how tile indices map to positions in the underlying tensor's tile grid.

- **Advancing dim**: `stride[i] = grid_cols_per_step` — tiles advance through the grid
- **Broadcast dim**: `stride[i] = 0` — same tile replicated along this dimension

## HINT: Arbitrary permutation of tensor can be expressed through a Bufferize + Streamify pair with proper strides.

## Function Signature

For the root node:
```python
def tiled_reference(dims: dict, tensors: dict) -> torch.Tensor:
```

For every non-root node, the user prompt's "Required Function Signature" block gives the **exact** signature you must produce — copy it verbatim. It has the form:
```python
def <node_name>(<arg_1>, <arg_2>, ..., *, out_shapes):
```
where the positional parameters are the named tiled inputs declared by the parent's call-site contract (also listed in the contract block above), and the keyword-only tail is the bare `*` separator followed by `out_shapes`. Do **not** collapse the positional list into `*intermediate_args` — that is a syntax error in combination with the keyword-only tail.

If your node's PyTorch reference returns a single tensor, your function returns a single tensor. If it returns a tuple of N tensors (e.g. ``return Q, K, V``), your function must return a tuple of the same length. ``out_shapes`` always has length N (a 1-tuple for single-output nodes).

## Off-Chip Sink (root only)

The root function (`tiled_reference`) is the only place where the kernel writes its result off-chip. It **must** terminate with a single `offchip_store(...)` whose argument is the stream that carries the kernel's output. This holds regardless of how the root's body is structured{root_orchestrator_alt_clause} — the final value must be wrapped in `offchip_store(...)`:

```python
def tiled_reference(dims, tensors):
    ...
    return offchip_store(<final_stream>)
```

Non-root functions **must not** call `offchip_store`. They hand a stream tensor up to their parent (via `return`); the parent (and ultimately the root) is responsible for the off-chip write. The regex compliance check rejects a root that omits `offchip_store`.

The judge will reject any function whose name or signature deviates from the one rendered in the user prompt.
