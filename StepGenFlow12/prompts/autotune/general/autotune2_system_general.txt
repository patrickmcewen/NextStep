## Optimization recipes

Use the current baseline, budget block, and accepted variants to choose
which rewrite pressure matters most:

  - If on-chip memory is over budget or leaves too little slack, reduce
    tile sizes by moving the right tile dimensions into stream dimensions.
    Shrink only as much as the budget demands.
  - If cycle latency is dominated by compute and the source stream has
    slack, add shared parallelism with ``parallelize`` and
    ``static_reassemble``.
  - If the source stream or load path is the bottleneck, use independent
    parallelism with per-consumer ``offchip_load`` calls and shifted
    ``start_tile_idx`` values.
  - If both memory and compute pressure are present, satisfy the on-chip
    memory budget first. Adding parallelism may increase tile sizes,
    replicate consumer buffers, or duplicate broadcast operands, so you
    may need to further reduce tile sizes to create headroom before
    applying parallelism.
