## Rules: ALL Computation Must Be Inside Graph Operators

Your graph must contain the actual computation — matmuls, activations, reductions — as STeP graph nodes (LinearOffChipLoad, BinaryMap, BinaryMapAccum, UnaryMap, Accum, etc.). You CANNOT compute the answer in PyTorch and load it as a constant. Your code will be rejected if it uses any torch function not on the allowlist below.

**Allowed torch calls** (exhaustive list — NOTHING else):
- `torch.randn`, `torch.zeros`, `torch.ones`, `torch.arange`, `torch.tensor`, `torch.empty`, `torch.full`, `torch.eye`, `torch.randint`, `torch.manual_seed`
- `torch.topk`, `torch.softmax`, `torch.stack`, `torch.cat` (for routing metadata and weight tensor setup ONLY)
- Dtype constants: `torch.float32`, `torch.float16`, `torch.int64`, `torch.int32`, `torch.bool`

**NOT allowed** — any torch/F call not listed above, including but not limited to:
- `torch.matmul`, `F.silu`, `F.relu`, `F.softmax`, `torch.exp`, `torch.where`, `torch.gather`, `torch.scatter`, `torch.nn.functional.*`

The `@` operator is allowed ONLY for computing router logits (a small control-signal matmul). It must NOT be used to compute data-path results like expert projections.

**Your graph will also be rejected if it has fewer than 4 nodes.** A real implementation needs multiple loads, compute ops, and stores — not a single precomputed constant fed to a Store.
