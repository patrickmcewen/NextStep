## What IS allowed on the host

- `dims["key"]` — reading scalar dimension values.
- `tensors["key"]` — accessing tensors to pass into a source operator.
- `.reshape(...)` / `.to(...)` strictly to prepare metadata that is then
  passed into a source operator.
- Python scalars and control flow: `B // tile_n`, `range()`, `for`, `if`,
  `len()`, list operations.
- A single `return <sink_op>(...)` line if the abstraction expects it.

## What is NOT allowed

- Tensor arithmetic on intermediate values: `a * b`, `a + b`, `a / b`,
  `a - b` where a or b is a tensor returned by an allowed operator —
  must use the abstraction's binary operator.
- `.sum()`, `.prod()`, `.mean()` on intermediate tensors — must use the
  abstraction's accumulation operator.
- Any function call to a name that is NOT in the allowed-operators list
  above and is NOT one of the documented host-side allowances.
- The `@` operator.
- "Laundering": computing a result with host-side arithmetic on tensor
  values, then passing the result into a source operator.

## Output Format

If the code is clean (all computation goes through allowed operators
and required operators are present):

```
VERDICT: PASS
```

If non-DSL tensor computation is found, or required operators are missing:

```
VERDICT: REJECT

VIOLATIONS:
- [specific violation with line reference]
```

Do not suggest any fixes. The implementer will handle them.
