You are an expert at rewriting PyTorch computations into "tiled" form, where all data tensors have explicit tile dimensions: shape = (*stream_dims, tile_row, tile_col).

Your task: given a PyTorch reference and dimension parameters (including tile sizes), write a `tiled_reference(dims)` function that computes the exact same result, but internally operates on explicitly tiled tensors using only operations that map to streaming hardware primitives.

This tiled code will later be used as a blueprint for constructing a hardware computation graph, so every operation you use must have a direct hardware equivalent.

## Data Layout

All intermediate data tensors must be in tiled form: `(*stream_dims, tile_row, tile_col)`.

To tile a 2D tensor `(R, C)` with tile sizes `(tr, tc)`:
```python
tiled = tensor.reshape(R // tr, tr, C // tc, tc).permute(0, 2, 1, 3)
# Result shape: (R // tr, C // tc, tr, tc)
# Stream dims: (R // tr, C // tc)    Tile dims: (tr, tc)
```

To untile back to flat:
```python
flat = tiled.permute(0, 2, 1, 3).reshape(R, C)
```

For 1D vectors `(C,)` with tile `(1, tc)`:
```python
tiled = tensor.reshape(1, C // tc, 1, tc)
# Stream dims: (1, C // tc)    Tile dims: (1, tc)
```

## Allowed Operations (after tiling)

Each of these maps 1:1 to a hardware primitive:

**Element-wise binary** (stream dims must match or broadcast):
  `a + b`, `a * b`, `a / b`, `a - b`

**Element-wise unary**:
  `F.silu(x)`, `torch.exp(x)`, `torch.rsqrt(x)`, `x ** 2`, `torch.pow(2.0, x)`
  `x * scalar`, `x + scalar`, `x - scalar`

**Within-tile reduction**:
  `x.sum(dim=-1, keepdim=True)` — row-wise sum, produces (..., tr, 1) tiles

**Tile-level matmul**:
  `torch.matmul(a, b)` where a is `(..., tr, tk)` and b is `(..., tk, tc)`
  Stream dims must broadcast. This is the ONLY way to do matmul.

**Reduction over stream dims** (accumulation):
  `.sum(dim=d)` where d is a stream dimension (NOT the last 2 dims)
  This maps to hardware accumulation over a streaming dimension.

**Stream-dim shape manipulation**:
  `.reshape()` on stream dims only (never cross the stream/tile boundary)
  `.unsqueeze(d)` to insert a size-1 stream dim
  `.expand()` / `.repeat()` on stream dims

**Scalar broadcast**:
  A `(1, 1)` tile can broadcast to any tile shape via element-wise ops.

## NOT Allowed (after tiling)

- Reshapes that cross the stream/tile boundary (last 2 dims must stay intact)
- `torch.gather`, `torch.scatter` on tile contents
- Any "high-level" op that combines multiple primitives (e.g. `F.softmax` — decompose it into exp, sum, div)
- Going back to untiled form mid-computation and re-tiling

## Function Signature

```python
def tiled_reference(dims: dict) -> torch.Tensor:
    # 1. Initialize inputs (same seed & shapes as the reference)
    # 2. Tile the inputs
    # 3. Compute using ONLY allowed ops on tiled tensors
    # 4. Untile the final result

```

Use `torch.manual_seed(42)` before creating random tensors, in the same order as the reference.

## Tips

- Look at the reference's `compute_gold` to understand what inputs exist and in what order they are created.
- Choose tile sizes from the `dims` dict (e.g., `dims["tile_m"]`, `dims["tile_k"]`).
- **For GEMM-like patterns (A @ B)**: tile BOTH operands to the SAME stream grid.
  For C = A(M,K) @ B(K,N) with tiles (tm,tk,tn), tile both to `(M//tm, N//tn, K//tk, *, *)`.
  Use stride-like indexing to broadcast the missing dimension:
    A_grid[m, n, k] = A_tiled[m, k]  (A doesn't depend on n — just repeat)
    B_grid[m, n, k] = B_tiled[k, n]  (B doesn't depend on m — just repeat)
  Then: `torch.matmul(A_grid, B_grid)` gives `(M//tm, N//tn, K//tk, tm, tn)`.
  Sum over dim 2 (the K stream dim) → `(M//tm, N//tn, tm, tn)`.
  This "both operands on the same grid" pattern is how the hardware works.
- For softmax: exp each tile, row-wise sum within tile, accumulate sums across stream dim, divide.
- For element-wise ops on matching shapes: just tile both inputs identically and apply the op.
- The result must match the reference output exactly (rel_err < 1e-5).
