## What You Are Doing

The hybrid code has STeP loads producing tiled tensors, then applies PyTorch ops like `torch.matmul(a, b)`, `F.silu(x)`, `a * b`. You replace these with STeP graph nodes that do the same thing when executed by the emulator.

## The Translation

**Before (hybrid — loads are STeP, compute is PyTorch):**
```python
# ... loads already produce tiled tensors via execute_values ...
z = torch.matmul(a_tiled, b_tiled)   # per-tile matmul
activated = F.silu(z)
scaled = activated * c_tiled          # element-wise multiply
```

**After (hybrid — loads and compute are STeP):**
```python
# ... loads produce STeP nodes (not yet executed) ...

# Compute nodes — wire them to load nodes in the graph
z = BinaryMap(graph, a_load, b_load,
              map_fn.Matmul(weight_transposed=False), False, 1024)
activated = UnaryMap(graph, z, map_fn.Silu(), False, 1024)
scaled = BinaryMap(graph, activated, c_load, map_fn.Mul(), False, 1024)

# Execute the graph to get tensor values
graph = infer_broadcast(graph)
values = execute_values(graph)

# CRITICAL: execute_values returns (1, *stream_dims, tile_r, tile_c).
# Always .squeeze(0) to drop the leading 1 before using in PyTorch ops.
result_tensor = values[scaled.instance_id].squeeze(0)

# Remaining ops (reduction, routing) stay as PyTorch for later passes
```

## STeP Compute Node Reference

**BinaryMap(graph, in1, in2, fn, write_back_mu, compute_bw)**
- Element-wise binary op. Both inputs must have identical stream shapes.
- `map_fn.Matmul()`: per-tile matmul `(tr, tk) @ (tk, tc) -> (tr, tc)`. No reduction — same stream shape.
- `map_fn.Mul()`, `map_fn.Add()`, `map_fn.Div()`: element-wise ops.
- Inputs can be STeP node references (the node object itself).

**BinaryMapAccum(graph, in1, in2, fn, init_fn, rank, write_back_mu, compute_bw)**
- Binary op + accumulation. `rank` = number of inner stream dims to reduce.
- `map_accum_fn.Matmul()`: matmul + sum over `rank` inner dims.
- Use this when the tiled code does `torch.matmul(a, b).sum(dim=reduce_dim)`.
- `init_fn`: typically `init_fn.Zero(shape=(out_tile_r, out_tile_c), dtype=Float32())`.
- NOTE: uses `map_accum_fn.Matmul()`, NOT `map_fn.Matmul()`.

**UnaryMap(graph, input, fn, write_back_mu, compute_bw)**
- Element-wise unary op. Shape preserved.
- `map_fn.Silu()`, `map_fn.Exp()`, `map_fn.Rsqrt()`, `map_fn.Square()`, `map_fn.Pow2()`
- `map_fn.MulImmediate(constant)`, `map_fn.AddImmediate(constant)`, `map_fn.SubImmediate(constant)`
- `map_fn.RowWiseSum()`: reduces tile columns to `(tr, 1)`.

## How It Executes (from functional.py)

**BinaryMap:**
```python
result = _apply_binary(fn, a, b)
# _apply_binary dispatches: Matmul -> torch.matmul(a, b), Mul -> a * b, Add -> a + b, Div -> a / b
```

**BinaryMapAccum (`_exec_binary_map_accum`):**
```python
# Apply per-tile map function
if isinstance(fn, map_accum_fn.Matmul):
    if fn.weight_transposed:
        mapped = torch.matmul(a, b.transpose(-2, -1))
    else:
        mapped = torch.matmul(a, b)

# Sum-reduce over the last `rank` stream dims (dim -3 = rightmost stream dim, before tile_r, tile_c)
for _ in range(rank):
    mapped = mapped.sum(dim=-3)
```

**UnaryMap:**
```python
result = _apply_unary(fn, inp)
# _apply_unary dispatches: Silu -> F.silu(x), Exp -> torch.exp(x), Rsqrt -> torch.rsqrt(x),
#   Square -> x**2, Pow2 -> torch.pow(2.0, x), MulImmediate -> x*c, AddImmediate -> x+c,
#   SubImmediate -> x-c, RowWiseSum -> x.sum(dim=-1, keepdim=True)
```

## Important: Stream Shape Matching

Both inputs to BinaryMap/BinaryMapAccum MUST have identical stream shapes. The load translator already handled this by using `stride=0` for broadcast dimensions. If inputs don't match, you have a load issue, not a compute issue — go back and fix the loads.
