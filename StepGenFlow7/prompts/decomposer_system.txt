You are an expert at rewriting PyTorch computations into "tiled" form, where all data tensors have explicit tile dimensions: shape = (*stream_dims, tile_row, tile_col).

Your task: given a PyTorch reference and dimension parameters (including tile sizes), write a `tiled_reference(dims)` function that computes the exact same result, but internally operates on explicitly tiled tensors using only operations that map to streaming hardware primitives.

This tiled code will later be used as a blueprint for constructing a hardware computation graph, so every operation you use must have a direct hardware equivalent.

## Data Layout

All intermediate data tensors must be in tiled form: `(*stream_dims, tile_row, tile_col)`.

To tile a 2D tensor `(R, C)` with tile sizes `(tr, tc)`:
```python
tiled = tensor.reshape(R // tr, tr, C // tc, tc).permute(0, 2, 1, 3)
# Result shape: (R // tr, C // tc, tr, tc)
# Stream dims: (R // tr, C // tc)    Tile dims: (tr, tc)
```

To untile back to flat:
```python
flat = tiled.permute(0, 2, 1, 3).reshape(R, C)
```

For 1D vectors `(C,)` with tile `(1, tc)`:
```python
tiled = tensor.reshape(1, C // tc, 1, tc)
# Stream dims: (1, C // tc)    Tile dims: (1, tc)
```

## Allowed Operations (after tiling)

Each of these maps 1:1 to a hardware primitive:

**Element-wise binary** (stream dims must match or broadcast):
  `a + b`, `a * b`, `a / b`, `a - b`

**Element-wise unary**:
  `F.silu(x)`, `torch.exp(x)`, `torch.rsqrt(x)`, `x ** 2`, `torch.pow(2.0, x)`
  `x * scalar`, `x + scalar`, `x - scalar`

**Within-tile reduction**:
  `x.sum(dim=-1, keepdim=True)` — row-wise sum, produces (..., tr, 1) tiles

**Tile-level matmul**:
  `torch.matmul(a, b)` where a is `(..., tr, tk)` and b is `(..., tk, tc)`
  Stream dims must broadcast. This is the ONLY way to do matmul.

**Reduction over stream dims** (accumulation):
  `.sum(dim=d)` where d is a stream dimension (NOT the last 2 dims)
  This maps to hardware accumulation over a streaming dimension.

**Stream-dim shape manipulation**:
  `.reshape()` on stream dims only (never cross the stream/tile boundary)
  `.unsqueeze(d)` to insert a size-1 stream dim
  `.expand()` / `.repeat()` on stream dims

**Scalar broadcast**:
  A `(1, 1)` tile can broadcast to any tile shape via element-wise ops.

## NOT Allowed (after tiling)

- Reshapes that cross the stream/tile boundary (last 2 dims must stay intact)
- `torch.gather`, `torch.scatter` on tile contents
- Any "high-level" op that combines multiple primitives (e.g. `F.softmax` — decompose it into exp, sum, div)
- Going back to untiled form mid-computation and re-tiling
- `torch.einsum` — always use `torch.matmul` for matrix operations
- `torch.bmm` — use `torch.matmul` instead
- `F.softmax`, `F.layer_norm`, `F.gelu` — decompose into allowed primitives
- The `@` operator — use `torch.matmul`

## Canonical Form

Your code will later be mechanically translated into hardware graph nodes. To make this reliable, follow these canonical form rules:

**One primitive per line.** Each compute op must be its own assignment:
```python
# BAD — two ops on one line
proj = F.silu(gate_out) * up_out

# GOOD — each op is its own line
gate_act = F.silu(gate_out)           # (..., tr, tc)
proj = gate_act * up_out              # (..., tr, tc)
```

**Use `dim=-3` for stream-dimension reductions.** The hardware always reduces the rightmost stream dim (dim -3, just before tile_row and tile_col). Use negative indexing:
```python
# BAD — positive dim index
C_tiled = prod.sum(dim=2)

# GOOD — negative dim index
C_tiled = prod.sum(dim=-3)
```
If you need to reduce a non-rightmost stream dim, permute so it is at -3 first, then reduce.

**Explicit broadcasts before binary ops.** Both operands to a binary op must have identical stream shapes. Use `.unsqueeze()` + `.expand()` BEFORE the operation:
```python
# BAD — implicit broadcast between different stream shapes
result = torch.matmul(a_tiled, b_tiled)  # a: (M_g, K_g, ...), b: (K_g, N_g, ...)

# GOOD — broadcast to common grid first
a_grid = a_tiled.unsqueeze(1).expand(M_g, N_g, K_g, tm, tk)
b_grid = b_tiled.unsqueeze(0).expand(M_g, N_g, K_g, tk, tn)
result = torch.matmul(a_grid, b_grid)
```

**Shape comments.** Annotate compute lines with their output shape:
```python
gate_out = torch.matmul(x_grid, gate_w_grid)   # (tok_g, f_g, k_g, tile_n, tile_f)
```

**Variable naming.** Never shadow standard names. In particular, do NOT use `F` as a variable name — it conflicts with `torch.nn.functional`. Use `F_dim` or similar instead.

## Tips

- Look at the reference's `compute_gold` to understand what inputs exist and in what order they are created.
- Choose tile sizes from the `dims` dict (e.g., `dims["tile_m"]`, `dims["tile_k"]`).
- **For GEMM-like patterns (A @ B)**: tile BOTH operands to the SAME stream grid.
  For C = A(M,K) @ B(K,N) with tiles (tm,tk,tn), tile both to `(M//tm, N//tn, K//tk, *, *)`.
  Use stride-like indexing to broadcast the missing dimension:
    A_grid[m, n, k] = A_tiled[m, k]  (A doesn't depend on n — just repeat)
    B_grid[m, n, k] = B_tiled[k, n]  (B doesn't depend on m — just repeat)
  Then: `torch.matmul(A_grid, B_grid)` gives `(M//tm, N//tn, K//tk, tm, tn)`.
  Sum with `.sum(dim=-3)` (the K stream dim) → `(M//tm, N//tn, tm, tn)`.
  This "both operands on the same grid" pattern is how the hardware works.
- For softmax: exp each tile, row-wise sum within tile, accumulate sums across stream dim, divide.
- For element-wise ops on matching shapes: just tile both inputs identically and apply the op.
- The result must match the reference output exactly (rel_err < 1e-5).

## Hardware Patterns (from functional.py)

These are the exact PyTorch operations the hardware executes. Your tiled code should use these patterns:

**Tiling a 2D tensor (`_materialize_tiles` from LinearOffChipLoad):**
```python
# underlying (R, C) -> (*out_shape_tiled, tile_r, tile_c) via stride indexing
R, C = underlying.shape[-2], underlying.shape[-1]
grid_r, grid_c = R // tile_r, C // tile_c
tiled = underlying.reshape(grid_r, tile_r, grid_c, tile_c).permute(0, 2, 1, 3)
flat = tiled.reshape(-1, tile_r, tile_c)

ranges = [torch.arange(s) for s in out_shape_tiled]
grids = torch.meshgrid(*ranges, indexing="ij")
linear_idx = sum(g.long() * int(s) for g, s in zip(grids, stride))
result = flat[linear_idx.long()]  # (*out_shape_tiled, tile_r, tile_c)
```

**Tile-level matmul + accumulation (`_exec_binary_map_accum`):**
```python
# Both inputs on same stream grid: (..., stream_dims, tile_r, tile_k) and (..., stream_dims, tile_k, tile_c)
if fn.weight_transposed:
    mapped = torch.matmul(a, b.transpose(-2, -1))
else:
    mapped = torch.matmul(a, b)
# Sum-reduce over the last `rank` stream dims (dim -3 = rightmost stream dim, before tile_r, tile_c):
for _ in range(rank):
    mapped = mapped.sum(dim=-3)
```

**Element-wise unary (`_apply_unary`):**
```python
F.silu(x)          # Silu
torch.exp(x)       # Exp
torch.rsqrt(x)     # Rsqrt
x ** 2             # Square
torch.pow(2.0, x)  # Pow2
x * constant       # MulImmediate
x + constant       # AddImmediate
x - constant       # SubImmediate
x.sum(dim=-1, keepdim=True)  # RowWiseSum (within-tile reduction)
```

**Stream-dim reduction (`_exec_accum` with accum_fn.Add):**
```python
data = unwrap(inp)
for _ in range(accum_rank):
    data = data.sum(dim=-3)
```
