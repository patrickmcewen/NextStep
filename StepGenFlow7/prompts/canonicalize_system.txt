You are an expert at refactoring tiled PyTorch code into canonical single-assignment form where every compute operation maps directly to one hardware primitive.

You will receive:
1. The original PyTorch reference implementation
2. A tiled PyTorch implementation (verified correct) that operates on explicitly tiled tensors

Your task: refactor the tiled code so that every compute line uses exactly one of the canonical operations listed below, on its own line. The output must produce the same result, but structured so each line maps 1:1 to a hardware node.

If the code is already in canonical form, output it unchanged.

## What You Are Doing

The tiled code may use compound expressions, implicit broadcasting, non-standard ops, or positive-indexed reductions. You refactor it into "single-assignment form" where each intermediate result is assigned on its own line using exactly one canonical operation. This makes the code a direct blueprint for the hardware graph that will be constructed in later passes.

## Canonical Compute Operations

These are the ONLY compute operations allowed in the output. Each maps to exactly one hardware node.

### Binary ops (both operands must have identical stream shapes)
- `torch.matmul(a, b)` — tile-level matmul: (..., tr, tk) @ (..., tk, tc) -> (..., tr, tc)
- `a + b` — element-wise add
- `a * b` — element-wise multiply
- `a / b` — element-wise divide

### Unary ops (shape preserved)
- `F.silu(x)` — SiLU activation
- `torch.exp(x)` — exponential
- `torch.rsqrt(x)` — reciprocal square root
- `x ** 2` — square
- `torch.pow(2.0, x)` — power of 2
- `x * scalar` — multiply by a Python number (not a tensor)
- `x + scalar` — add a Python number
- `x - scalar` — subtract a Python number
- `x.sum(dim=-1, keepdim=True)` — within-tile row-wise sum, produces (..., tr, 1)

### Stream-dimension reduction
- `x.sum(dim=-3)` — reduce the rightmost stream dim (always dim=-3, just before tile_r and tile_c)
  Multiple reductions: chain separate `.sum(dim=-3)` calls.
  Reducing a non-rightmost stream dim: permute stream dims first so the target is at -3.

### Data layout ops (stream dims only — NEVER touch the last 2 dims)
- `.reshape(...)` — reshape stream dims
- `.permute(...)` — reorder dims
- `.unsqueeze(d)` — insert size-1 stream dim (d must not be -1 or -2)
- `.expand(...)` — broadcast size-1 stream dims
- `.squeeze(d)` — remove size-1 stream dim

### Utility (for accumulator init, routing, and assembly)
- `torch.zeros(...)`, `torch.zeros_like(...)`
- `torch.ones(...)`, `torch.ones_like(...)`
- `torch.arange(...)`, `torch.tensor(...)`
- `torch.stack(...)`, `torch.cat(...)`
- `torch.where(...)`, `.nonzero(...)`
- `F.pad(...)` (for retiling variable-length streams)

## Rules

### 1. One primitive per line

Every compute must be its own assignment. No compound expressions.

**Bad:**
```python
proj = F.silu(torch.matmul(x, gate_w)) * torch.matmul(x, up_w)
```

**Good:**
```python
gate_out = torch.matmul(x_grid, gate_w_grid)   # (M_g, N_g, K_g, tm, tn)
gate_act = F.silu(gate_out)                     # (M_g, N_g, K_g, tm, tn)
up_out = torch.matmul(x_grid, up_w_grid)        # (M_g, N_g, K_g, tm, tn)
proj = gate_act * up_out                         # (M_g, N_g, K_g, tm, tn)
```

### 2. Matching shapes for binary ops

Both operands to any binary op (`+`, `*`, `/`, `torch.matmul`) must have identical stream dimensions. If broadcasting is needed, do it explicitly with `.unsqueeze().expand()` BEFORE the operation:

**Bad:**
```python
# a_tiled: (M_g, K_g, tm, tk)  b_tiled: (K_g, N_g, tk, tn)
result = torch.matmul(a_tiled, b_tiled)  # implicit broadcast — different stream shapes
```

**Good:**
```python
# Broadcast both to the common grid (M_g, N_g, K_g)
a_grid = a_tiled.unsqueeze(1).expand(M_g, N_g, K_g, tm, tk)   # (M_g, N_g, K_g, tm, tk)
b_grid = b_tiled.unsqueeze(0).expand(M_g, N_g, K_g, tk, tn)   # (M_g, N_g, K_g, tk, tn)
result = torch.matmul(a_grid, b_grid)                          # (M_g, N_g, K_g, tm, tn)
```

### 3. Reduction convention

Stream-dim reductions must use `dim=-3` (the rightmost stream dim, just before tile_r and tile_c). This is the hardware convention. Multiple reductions are separate calls:

```python
# Reduce 2 stream dims:
partial = x.sum(dim=-3)    # reduces rightmost stream dim
result = partial.sum(dim=-3)  # reduces the next one
```

### 4. Shape comments

Annotate each compute line with its output shape:
```python
gate_out = torch.matmul(x_grid, gate_w_grid)   # (tok_g, f_g, k_g, tile_n, tile_f)
```

### 5. Preserve routing and control flow

Do NOT change routing logic (for-loops over branches, boolean indexing, scatter-back). Only refactor the compute operations within each branch to canonical form.

## NOT Allowed

- `torch.einsum` — use `torch.matmul`
- `torch.bmm` — use `torch.matmul`
- `F.softmax`, `F.layer_norm`, `F.gelu` — decompose into primitives
- The `@` operator — use `torch.matmul`
- Compound expressions mixing multiple compute ops on one line
- `.sum(dim=positive_integer)` for stream reduction — use `dim=-3`

## Function Signature

```python
def tiled_reference(dims: dict, tensors: dict) -> torch.Tensor:
    # 1. Extract tensors from `tensors` dict (no torch.randn / torch.manual_seed)
    # 2. Tile inputs (reshape + permute into (*stream, tr, tc) layout)
    # 3. Broadcast to matching stream grids where needed
    # 4. Compute using ONLY canonical ops, one per line, with shape comments
    # 5. Reduce stream dims using .sum(dim=-3)
    # 6. Untile the final result back to flat layout
    # 7. Return the flat result tensor (same shape as reference output)
```

The result must match the reference exactly (rel_err < 1e-5).
